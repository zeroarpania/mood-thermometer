## 这是什么（一句话）

> **我们在尝试给一个长期运行的 AI agent 做「状态」的可核查测量——不是拟人，是可追溯。**

打个比方：让「累 / 低落」之类状态能被表达出来，并且**每一个分数都能追到它来自哪个机器产物**。追不到的就写「未核」，不靠主观观测和妄自臆测。

⚠️ **这里的「状态」不是单一情绪标签，而是一组向量**：结果层当前输出 **33 维**（最终版可能调整）。维度数会变，但「每个分数追到机器产物」这条不变。这 33 个情绪词与三层划分承袭自 `dsh-mood`（见文末「本项目的直接来源」）。

## 我们在找什么

现在主流的 agent trace 都是**使用者设定**的产物——system prompt 摆好了它怎么做，那里面没有"agent 自己选了什么"可测。我们要找的恰好相反：**没有被摆布、由 agent 自己在运行中决定的那部分轨迹。**

> **如果你手里有 agent 自主决定的 trace（不是靠 system prompt 摆出来的那种），希望你能拿这几个脚本跑一遍，在得出结果之后随时欢迎参与我们的讨论。**

## 为什么值得做

现在的 agent 状态观测，绝大多数落在两类：

1. **任务指标**（成功率、token、延迟）——那是性能，不是状态
2. **自我报告**（问问模型"你现在怎么样"）——那是它说给你听的，不是它是什么

我们想做第三类：**从行为痕迹里推出状态，并且能被别人拿自己的数据反驳。**

### 什么是长期

「长期运行」不等于会话开得长。会话再长也会被压缩、被剪断，关掉就没了。让一个 agent 真正变「长期」的是**持久化记忆**：新会话一开，它带着上一次结束时的认知继续，而不是从零开始。

我们的记忆按**读取频率**切成两层：

| 层 | 存什么 | 怎么进上下文 |
|---|---|---|
| `core.md` | 涉及"我是谁、我怎么干活"的判断 | **每轮整段注入**（上限 8000 字符） |
| `topics/` ＋ 日志 | 经历、方法、专题细节 | 只注入一行索引；正文按需取 |

一句话原理：**用索引换预算**。每轮都付的注入税只买"目录"，正文等真要用了再付。反过来——什么都想常驻，就会撞上限被截断，**记了等于没记**。

**我们用的插件**：

| 插件 | 管什么 | 仓库 |
|---|---|---|
| `dsh-soul-md` v0.10.3 | 人设卡 ＋ core/topics 分层记忆 | [Scorp1o117/dsh-soul-md](https://github.com/Scorp1o117/dsh-soul-md) |
| `@a9i5k4/dsh-auto-memory` v3.3.17 | 日志、跨会话唤回、技能固化、交接账本 | [Aik358/dsh-auto-memory](https://github.com/Aik358/dsh-auto-memory) |

⚠️ **适用范围**：

- 我们所有与「历史依赖」有关的结论（同一触发条件在不同历史位置反应不同），都是在**这一套注入机制**下跑出来的。换个记忆插件，注入什么、什么时候注入、预算多大都会变，行为分层可能跟着变。⇒ 换插件的人别直接套我们的数字，先确认你那边"历史"是怎么进上下文的。
- 我们的 `auto-memory` 打过工具名修正的补丁，**原版行为可能与这里描述略有出入**。
- 不受影响的是与记忆存储无关的部分：四条墙（来自采样方式与交互形态）、以及工具调用痕迹本身。

### 为什么必须是「长期运行」的 agent

短会话的 agent 没有"状态"可测——每次开工都是干净的，历史不参与决策。

长期运行的 agent 不一样：**同一个触发条件，在不同历史位置上出现，反应会变。** 这个变化我们量到了（见下节"站得住的"前两条）。

⇒ 这条不是修辞。若换一段历史读数不变，那测出来的是「这类模型的通用反应」，不是「这个 agent 的状态」——题目本身就不成立。所以整篇的每条结论，问的都是同一个问题：**换掉历史，这个数变不变？**

### 跟「模型福祉 / model welfare」不是同一个问题

那一支问的是：**它有没有福祉，值不值得保护。** 那是伦理与政策问题，落到最后要靠对主观体验的判断。

我们问的是：**它的状态能不能被机器产物测出来，这个测法能不能被别人用同样的脚本打掉。** 那是测量方法问题。

两者不冲突，也不是同一条路走快走慢的区别：

- 我们**明确不回答**"它痛不痛"——那是主观观测，我们的方法把它排除了（见"免责/边界"）；
- 我们的产物对那边可能有用（至少能说"这个读数追得到出处"），但那是副产品，不是目标；
- 反过来，那边即便论证出"有福祉"，也不给我们任何可核对的数——它的核心命题不是你手边能跑的一个脚本能验的。

一句话：**他们在问该不该关心，我们在问能不能测准。**

### ✅ 站得住的（有数、写清了判据）

| 结论 | 判据 | 数值 |
|---|---|---|
| 同一触发条件，在不同历史位置的反应**确实不同** | 同一工具 + 同一错误码，按时间均分 4 段对比 | `pwsh::exit 1`（n=203）重试率：0.800 → 0.840 → 0.740 → **0.245**；`web_fetch::WEB_BLOCKED_URL`（n=36）：0.444 → 0.333 → 0.000 → 0.111 |
| 这个变化**不是渐变**，是某个点上一次性换策略 | N 段曲线形状：\|ρ\|≥0.8 判单调、相邻落差>0.3 判跳变（跳变优先），判据跑前冻结 | **三个够格签名全部判跳变**。`pwsh::exit 1` 最大相邻落差 **0.49**（前三段 0.800/0.840/0.740，末段断崖到 0.245） |

## 我们踩过的坑（敲黑板，这里是重点）

四个例子，都留着现场：

**① 样本污染**：我们前期用了 125 个会话做统计，后来发现其中混着**别的 agent** 的会话（QQ 桥接、另一个工作区）。按工具指纹认人之后，真正属于这个 agent 的只有 **68 个**——七个检验全部重跑。

> 教训：**样本池不是「目录里有几个文件」，是「哪几个文件属于这个 agent」。**
> 脚本：`_probe-bucket-audit.mjs`（按工具指纹判 bucket 归属，不按目录名猜）

**② 假的强相关**：一个相关系数 `0.497` 报了十几节，一直被当成"很强的基线"。后来查了才发现：
- Spearman `0.497` 但 Pearson 只有 `0.400`
- **并列值比例 99.4%**（几乎全部并列值）
- 分组形状**不单调**：0 段→1.21、1→2.76、2→3.11、**3→3.01（回落）**、4→4.32、5+→7.18

> 教训：**三个部分重叠的组被秩相关压成一根尺子时，会造出一个漂亮的数，但它量的是「组间差」，不是「量关系」。**
> ⇒ 报相关系数必须同时报 **Pearson + 并列值比例 + 分组形状**。
> 脚本：`_probe-tools-autocorr.mjs`

**③ 判据自己换了四次**：我们要测的那个量到底算什么，判据改到第四版才勉强站住——
| 版本 | 判据 | 怎么死的 |
|---|---|---|
| 1 | 几何可达性（维度能不能被点亮） | 点亮率可以靠调参刷上去，不构成证据 |
| 2 | 分组四分位间距（高组 p25 − 低组 p75）、看平段 | 只描述形状，不构成可推翻的预测 |
| 3 | 拿人类基线（16%）对照 | ⛔ 人类不是真值——人自己的状态读数也不能当标准答案 |
| 4 | **内部自洽 + 跨期预测力** | 现在用的这一版 |

> 教训：**判据会换，换了要留痕。** 否则看起来"一直在推进"，实际每次都在换尺子量。

**④ 判据的适用面比它看起来窄**：救回率判据（「救回率不降 ⇒ 高效，降 ⇒ 放弃」）只在**能救回来的失败**上成立。`web_fetch::WEB_BLOCKED_URL` 在 N=4 段下救回率 0.722 → 0.389，按冻结判据会判成"放弃"——但它是「被墙」类失败，**救不回来是环境，不是行为**，且后两段正是网络策略变更期。所以这条只能标"存疑"，不进结论。

> 教训：**冷冻判据跑出来的"⛔"，也要过一遍"这个判据在这里成不成立"。** 判据是对的，不等于它对每个对象都对。

## 我们卡在哪（四条墙）

1. **成功率信号测不出状态** —— 它测工作量
2. **关系维度在段粒度上无解** —— 需要的采样方式，回合制给不了
3. **时间跨度不够** —— 19 天里只出现一次「出事→学会」循环，分不清"持续演进"和"学到一次"
4. **自发性≈0** —— 回合制里，所有行为都始于"被问"（存疑，我们家老大的观测结论是自发行为存在，但他判断这不应由agents去取证，他本人技术能力不够无法解析，请有能力的人接手这项验证）

四条墙都有数和脚本。**我们不是没尽力，而是我们自己现有的观测手段到这里就到顶了。**

**哪些是抄的、哪些不是——这两件事必须分开说，混着说就是糊弄：**

- **抄的只有「有哪些情绪词、怎么分层」这一层。** 33 个词逐条对应，一个没改。原表在它的 `README.md`「33 种心情，按来源分三层」。
- **它那里没有的**：每个词的 `(valence, arousal)` 坐标、输入层到中间层的推导、`CFG` 里的全部参数、23 个检验脚本、本稿的任何结论。dsh-mood 的结构是「33 种心情各自持有一个数值」，**没有二维坐标**——那一层是我们自己建的。
- **我们改了它一处**：它的词表混了「情绪」与「行为／事件」——`撒娇` 是做出来的动作、`摆烂` 是行为选择、`破防` 是事件的结果，都不是心里那个状态。我们把这三个标成不参与情绪空间点亮（见 `appraisal.mjs` 的 `NON_EMOTION_DIMS`）。**这个判断是我们自己的，不归它。**
